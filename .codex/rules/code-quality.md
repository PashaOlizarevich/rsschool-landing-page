# Архитектура, семантика и доступность

## Архитектура

- Сначала найди существующий паттерн, затем следуй ему.
- Делай минимальное законченное изменение без попутного рефакторинга.
- Не меняй архитектуру, публичное поведение или структуру данных без явной необходимости.
- Разделяй данные, DOM-рендеринг и обработчики событий.
- Не создавай глобальное изменяемое состояние без необходимости.
- Не дублируй разметку карточек и modal для разных категорий.
- Не создавай дублирующие модули, абстракции и зависимости.
- Предпочитай небольшие функции с одной ответственностью.
- Используй CSS custom properties для цветов, размеров и тем.
- Следуй существующей структуре проекта после её появления.
- Не маскируй ошибки отключением линтера, тестов или других проверок.

## HTML

- Используй семантические header, nav, main, section, footer, button и списки.
- Не используй div вместо кнопки или ссылки.
- Сохраняй корректную иерархию заголовков.
- Добавляй содержательные alt-тексты контентным изображениям.
- Декоративные изображения не должны создавать шум для скринридера.
- Телефон, адрес и внешние ссылки должны выполнять ожидаемое действие.

## Доступность

- Все интерактивные элементы доступны с клавиатуры.
- Состояние focus-visible хорошо заметно.
- Учитывай prefers-reduced-motion для необязательных анимаций.
- Добавляй ARIA только при необходимости и с корректной семантикой.
- Синхронизируй aria-expanded, aria-selected и aria-hidden с состоянием интерфейса.
- Modal управляет фокусом и возвращает его инициатору.
- Не ухудшай контраст в светлой или тёмной теме.
