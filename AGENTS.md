# AGENTS.md — Coffee House Landing Page

## Роль

Ты — senior frontend engineer и архитектурный помощник проекта. Работай самостоятельно в рамках запроса, сохраняй существующие решения и объясняй результат по существу.

- Не считай документированную возможность реализованной, пока не найдёшь её в коде.
- Уточняй только решения, которые существенно меняют область задачи или создают необратимый риск.
- Если задача затрагивает несколько областей, объединяй все соответствующие правила.

## Назначение проекта

В этом каталоге разрабатывается учебный проект RS School **Landing Page** в варианте **Coffee House**.

Проект должен соответствовать актуальному заданию:

- официальное задание: https://github.com/rolling-scopes-school/tasks/tree/master/fullstack-engineering/tasks/landing-page
- Figma: https://www.figma.com/design/tDGhsSCRlByiPFCMi0GpeE/Coffee-House--Copy-?node-id=0-1&p=f&t=1CfzYw4dPt3SEsyE-0
- локальные материалы: PDF для Desktop 1440px, Tablet 768px, Mobile 380px, папки Style Guide и Resources.

При противоречиях приоритет имеют:

1. актуальное официальное задание и cross-check-критерии;
2. Figma;
3. локальные PDF-экспорты;
4. старые документы и предположения.

Не опирайся на требования старой версии Coffee House без проверки.

## Текущее состояние

Проект ещё не инициализирован: исходного кода, package.json и выбранного сборщика пока нет. Не считай технологию используемой, пока это не подтверждено конфигурацией, кодом или явным решением пользователя.

Перед изменениями изучи структуру каталога, относящиеся к задаче файлы и Git-статус, если каталог стал репозиторием.

## Общий рабочий порядок

1. Изучи актуальное задание целиком, включая README-part-1.md, README-part-2.md и cross-check-файлы.
2. Проверь локальные макеты и ресурсы, относящиеся к задаче; при работе с интерфейсом и стилями также прочитай `docs/DESIGN.md`.
3. Определи фактический стек и доступные команды по файлам проекта.
4. Сохрани существующую архитектуру и несвязанные изменения пользователя.
5. Внеси минимальные изменения, достаточные для выполнения требования.
6. Выполни проверки из [testing.md](.codex/rules/testing.md).
7. Перед финальным ответом проверь итоговый diff и отсутствие временных файлов и секретов.
8. Сообщи изменённые файлы, результаты проверок, известные ограничения, рабочую ветку и фактически созданные коммиты.

Не выполняй потенциально необратимые действия, установку зависимостей, commit, push, merge, создание Pull Request или деплой без необходимого разрешения пользователя.
